# FinOps Workflow Guide

> **When to perform FinOps reviews in the development lifecycle**

This guide answers the core question: **when do I need to think about cost?**

---

## The Optimization Loop

```
Data collection (Kubecost, VPA, billing APIs)
   ↓
Analysis (analyze-rightsizing.py, reserved-capacity-advisor.py)
   ↓
Alert or report fires
   ↓
Engineer follows optimization-runbook.md
   ↓
generate-optimization-pr.py creates the change
   ↓
PR reviewed and merged
   ↓
Cost reduction realized within 24-48 hours
   ↓
Cost report confirms savings -> loop closes
```

### Time To Value

| Optimization type | Time to identify | Time to implement | Time to realize savings |
|---|---|---|---|
| Resource rightsizing | Immediate (VPA running) | 1-2 days (PR review) | 24-48 hours after merge |
| Unused volumes | Daily (detect-unused-volumes.py) | 1 hour | Immediate after deletion |
| Reserved capacity | Quarterly (advisor script) | 1 week (approval + commitment) | Next billing cycle |
| Cross-cloud migration | Monthly (normalize-cloud-costs.py) | Weeks-months | Next billing cycle |

## The Four FinOps Moments

### Moment 1: Writing Terraform (Infrastructure Changes)

**Who**: Developer or Platform team writing Terraform
**What**: Infracost runs automatically in CI/CD
**Action required**:

| Increase | Action |
|----------|--------|
| < 10% and < $100/month | No action — merge when ready |
| 10–20% or $100–500/month | Review the cost breakdown; note in PR description |
| > 20% or > $500/month | Document justification, notify FinOps team, may need approval |

Use the Infracost templates from `finops/cicd/` to enable this automatically.

---

### Moment 2: Creating Kubernetes Manifests

**Who**: Developer adding a new service or workload
**What**: Manual checklist before deploying
**Action required**:

1. **Add cost labels** (required, enforced by Kyverno policy):
   ```yaml
   finops.org/costcenter: "engineering"
   finops.org/environment: "production"
   ```
2. **Set explicit resource requests and limits** (required, enforced by policy)
3. **Estimate monthly cost** using the quick formula:
   ```
   Monthly ≈ (CPU_cores * $0.048 + RAM_GiB * $0.006) * 730
   ```
4. **Check team budget headroom** in the [Budget Tracking dashboard](https://grafana.internal.company.com/d/finops-budget-tracking)

---

### Moment 3: Pre-Production Review

**Who**: Developer, reviewed by tech lead
**What**: Final FinOps review before production deploy
**Action required**:

1. **VPA recommendations**: Run `python finops/scripts/analyze-rightsizing.py --namespace <staging-namespace>`
   - Implement high-priority recommendations (> 20% savings) before deploy
   - Document why medium/low recommendations are being deferred
2. **Verify labels are present**: `python finops/scripts/validate-cost-tags.py --namespace <namespace>`
3. **Add FinOps PR checklist** to the production promotion PR

---

### Moment 4: Monthly Cost Review

**Who**: FinOps practitioner, engineering leads
**What**: Scheduled monthly review
**Action required**:

1. Review the monthly cost report (auto-generated by CronJob)
2. Review the [Rightsizing Opportunities dashboard](https://grafana.internal.company.com/d/finops-rightsizing) — address top 5 items
3. Check for unused volumes: `python finops/scripts/detect-unused-volumes.py`
4. Review reserved capacity candidates: `python finops/scripts/analyze-reserved-capacity.py --all-namespaces`
5. Update team budget thresholds in `finops/config/budgets.yaml` if needed

---

## Pre-Production FinOps Review Process

For any deployment to production of a **new service** or **significant change** (> 3 months of development):

1. Run the rightsizing analyzer against staging (after 24h of staging data)
2. Implement VPA recommendations with > 20% savings
3. Estimate monthly production cost
4. If cost > $500/month, get FinOps practitioner sign-off
5. Fill in the PR checklist in your promotion PR

**Timeline**: Allow 1-2 business days for FinOps review if cost > $500/month.

---

## Major Change Review Process

A **major change** that requires FinOps review is any change that:

- Adds a new data processing pipeline or ML training workload
- Adds GPU workloads (always requires approval)
- Increases resource requests by > 2x for existing workloads
- Creates new cloud infrastructure costing > $500/month
- Adds new cloud regions or availability zones

For these changes:
1. File a FinOps review request in `#finops-requests` Slack channel
2. Include estimated monthly cost and business justification
3. Allow 2-3 business days for review
